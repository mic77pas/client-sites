# Nik Karpov — portfolio

Next.js 16 (App Router) + Tailwind CSS 4. Every page is statically generated.

```bash
npm install
npm run dev      # http://localhost:3000
npm run build
npm run media    # process photos/video after adding or changing originals
```

## Structure

```
app/                  routes: / · /work · /work/[series] · /film · /about · /contact
components/           UI (Lightbox, JustifiedGallery, VideoPlayer, InquiryForm, …)
content/
  portfolio.ts        ← edit: series names/order, photo titles + alt text, homepage picks
  films.ts            ← edit: film list (local file, YouTube or Vimeo)
  site.ts             ← edit: email, socials, services copy
  media.json          generated by `npm run media` — don't edit by hand
lib/                  data helpers + the next/image loader
media/                full-resolution ORIGINALS (inputs only, never served)
  photos/<series>/    one folder per series
  video/              source clips (+ optional <name>.json, e.g. {"posterAt": 4.6})
  brand/              logo, cutout, portrait sources
  archive/            old site assets not used by the redesign (kept, not deployed)
public/media/         generated web derivatives (committed, deployed)
public/brand/         generated logo mark / cutout
scripts/media.mjs     the media pipeline
```

## Adding photos

1. Export from Lightroom at full size into `media/photos/<series>/`
   (the folder name is the series; existing ones: `people`, `events`, `sports`, `promo`, `street`, `animals`).
2. `npm run media`. Only new or changed files are processed.
3. Optional: in `content/portfolio.ts`, give each new photo a `title` and `alt` text
   (ids are listed in `content/media.json`), and add it to a series `order` or to `featured`.
   Photos without text still appear, with a generic caption.
4. Commit `public/media/`, `content/media.json` and any `content/*.ts` changes.

A new folder becomes a new series automatically. Add it to `categories` in
`content/portfolio.ts` to name it, describe it and choose its cover.

## Adding film

- **Short reels / loops** → drop the file in `media/video/`, run `npm run media`, then add
  `{ kind: "file", video: "<id>" }` to `content/films.ts`. Needs ffmpeg on PATH (or `FFMPEG_PATH`).
- **Anything longer than ~30 s** → upload to YouTube or Vimeo and add
  `{ kind: "youtube", youtubeId }` / `{ kind: "vimeo", vimeoId, poster }`. Streaming is free
  and adaptive, and nothing is stored in the repo. Players only load when someone presses play.

## How media is stored and served

Originals are 10–28 MB each. Shipping them makes the site slow and burns Vercel
image-optimisation quota and Git LFS bandwidth. The pipeline handles this instead:

| | Where | Size |
|---|---|---|
| Original | `media/photos/…` (Git LFS / or kept locally) | ~15 MB |
| Web derivatives | `public/media/photos/…-{480,960,1440,2048}.webp` (plain git) | ~0.7 MB total per photo |
| Placeholder + EXIF | `content/media.json` (inline blur, ~300 bytes) | — |

- `next/image` uses a **custom loader** (`lib/image-loader.ts`) that picks the right pre-made
  width. Nothing is resized on request, so no Vercel image quota is used, and
  every file is a static asset on Vercel's CDN.
- Derivatives are **not** in Git LFS (see `.gitattributes`), so Vercel builds don't need LFS.
  Once this is merged you can turn **off** "Git LFS" in the Vercel project settings.
- New originals are git-ignored by default (see `.gitignore`), so only the small
  derivatives grow the repo. Keep originals in your Lightroom catalogue or a cloud drive.
  Existing originals stay tracked; delete the ignore lines if you'd rather version everything.

**When the library gets big** (several hundred photos, or the repo passes ~500 MB),
move `public/media/` to object storage such as Cloudflare R2 (no egress fees) or Vercel Blob.
Upload the folder as-is, then set:

```
NEXT_PUBLIC_MEDIA_BASE_URL=https://<your-bucket-domain>
```

The loader prefixes every photo URL with it. No other code changes are needed.

## Light / dark theme

Colours are CSS variables in `app/globals.css` (`--paper`, `--ink`, `--mute`, …) with a
light set on `:root` and a dark set for `prefers-color-scheme: dark` / `data-theme="dark"`.
Tailwind classes (`bg-paper`, `text-ink`, …) point at them, so components never hard-code
a mode. The `dark:` variant follows the same rules if a one-off override is needed.

- Default: follows the visitor's OS setting.
- The sun/moon button in the header saves an explicit choice (`localStorage["nk-theme"]`).
  Picking the mode that matches the OS clears it again.
- A tiny inline script in `app/layout.tsx` applies a saved choice before first paint (no flash).
- `night-*` colours (film band, inquiries band, lightbox) stay dark in both modes.

## Environment

| Variable | Purpose |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | Canonical URL for metadata/sitemap. Falls back to Vercel's production URL. |
| `NEXT_PUBLIC_MEDIA_BASE_URL` | Optional CDN/bucket origin for `public/media` files. |
| `FFMPEG_PATH` | Optional path to ffmpeg for `npm run media`. |
